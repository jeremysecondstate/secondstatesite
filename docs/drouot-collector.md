```javascript
  timezone: 'America/New_York'

await collector.writeCapture();
collector.summary();
```

## Capture and validation

The collector writes `capture.json` with this public capture structure:

```text
format: "secondstate-drouot-browser-capture", version: 1, exported_at
window: {start_date, end_date, time_zone}
auctioneers: {id: name}
searches: [{artist, source_url, pages: [{
  page_url, captured_at, page, total_pages, total_results,
  request_url, status, content_type,
  lots: [public allowlisted source fields],
  cards: [{id, url, heading, description, text, image_url}]
}]}]
```

`writeCapture()` also saves completion and pending/failure progress in `collection-progress.json`; `summary()` returns the current counts. That progress flag does not replace the importer's independent manifest, scope, pagination, total and ID checks. Keep every search in the capture, including complete searches with no eligible lots.

The normalizer is `catalogapp/watchlist_drouot_pages.py`; the preview/sync CLI is `scripts/import_drouot_capture.py`. Drouot data must not enter the strict Invaluable snapshot or bundle validators. The Drouot validator requires:

- Matching primary artist credit at the start of **both** the source description and card heading (`h3`), using the canonical artist or maintained query alias. An arbitrary name mention or the bookmark label alone is insufficient. Retain explicit qualifiers such as `after`, `attributed to` or `school of` in the visible source artist, title and description, and record review flags. Qualified credits are legitimate source observations; do not recast them as unqualified authorship. Reject unresolved multiple-artist credits and unrelated mentions.
- An explicit print technique describing the offered work, before provenance or biography. A print word in a quoted exhibition title, shipping text or a discussion of other works is insufficient. Record unknown medium and unrelated matches as audit rejections. Do not add an authenticity filter: qualified source credits remain observations with visible qualifiers and review notes.
- Actual Drouot lot IDs, canonical URLs, sale IDs where present, auction-house identity and source observation times. Check API lot IDs against card IDs. Repeated same-source sightings retain matching scopes and one coherent lot; investigate conflicting duplicates.
- Correct sale instants from Unix **seconds**: use `bidEndDate` for `ONLINE` and `date` for `LIVE`. Compute today's New York date through Sunday at the end of the following calendar week, inclusive, and convert the source instant consistently into that window. Audit undated, posted, ended and out-of-window lots as rejections.
- Source `currencyId` as its observed ISO currency, verified against the visible value; do not guess a numeric currency map. A zero placeholder `currentBid` is absent, not an actual bid. Do not infer a bid count.

Keep Drouot identities distinct from Invaluable identities. Report possible cross-site duplicates for review with auction house, sale, lot number and source URLs; never automatically merge using fuzzy artist/title similarity.

The watchlist API's `horizon_days=7` readback includes public lot fields from seven days before the Calendar's current day through seven days after it, plus undated lots. Its global identity keys cover saved nonsuperseded lots beyond that horizon, but keys alone cannot verify their fields or Calendar database IDs. Collect public monthly Calendar DOM rows for every accepted observation outside the API horizon. Pass repeated `--dom` arguments when the window crosses months. Do not report complete field verification while the auditor says a readback is unavailable.

For each needed month, open the real Calendar month and extract the public projection **one day at a time**. The browser transport truncates returned arrays at 2,000 rows; this is a transport limit, not a Calendar limit. Compute the total inside the browser, combine the smaller day arrays in Node, and assert the combined count before saving. If a day reaches that transport limit, split it further rather than accepting a truncated result. Never dump the full embedded object or staff research, purchase flags, account data or credentials:

```javascript
const calendarMeta = await calendarTab.playwright.evaluate(() => {
  const node = document.getElementById('auction-calendar-data');
  if (!node) throw new Error('Calendar month data is unavailable');
  const data = JSON.parse(node.textContent);
  return {
    days: Object.entries(data).map(([day, rows]) => ({ day, count: rows.length })),
    totalRows: Object.values(data).reduce((count, rows) => count + rows.length, 0)
  };
});
const publicFields = [
  'id', 'date', 'artist', 'title', 'auction_house', 'sale_title', 'lot_number',
  'medium', 'location', 'estimate_low', 'estimate_high', 'current_bid',
  'bid_count', 'currency', 'sold_price', 'sold_currency', 'lot_url',
  'sale_url', 'image_urls', 'event_at', 'ended'
];
const publicRows = [];
for (const { day, count } of calendarMeta.days) {
  if (count >= 2000) throw new Error('Split this Calendar day into smaller chunks');
  const dayRows = await calendarTab.playwright.evaluate(({ fields, day }) =>
    JSON.parse(document.getElementById('auction-calendar-data').textContent)[day]
      .map(row => Object.fromEntries(fields.map(field =>
        [field, field === 'date' ? day : row[field] ?? null]
      ))), { fields: publicFields, day }
  );
  if (dayRows.length !== count) throw new Error('Calendar day readback is incomplete');
  publicRows.push(...dayRows);
}
if (publicRows.length !== calendarMeta.totalRows)
  throw new Error('Calendar month readback is incomplete');
await fs.writeFile(`${runDir}/calendar-dom-after-november.json`, JSON.stringify(publicRows, null, 2));
```
